**Goal:** Ship the smallest honest version of follow-the-donors: a district choropleth of PAC money, tappable, searchable, in a risograph visual language where registration quality encodes how certain the data is.

**Architecture:** Stages 01–06 are done and the data is ready. Three more numbered stages turn it into static artifacts; the frontend is React + Vite + MapLibre reading those artifacts from R2 through the existing Worker. No backend, no DuckDB-WASM, no database.

**Tech Stack:** Python 3.14, DuckDB 1.5.5 (pinned), tippecanoe, React 18, Vite 5, MapLibre GL JS 4, pmtiles 3, Vitest.

**Spec:** `docs/superpowers/specs/2026-09-18-phase-4-aggregation.md` (stage 06) and `2026-09-18-phase-3-districts.md` (vintage + ZIP resolution). Read `CLAUDE.md` first — its invariants are binding.

## Global Constraints

- **No individual is ever named.** v1 publishes no individual-level data at all, which is the cheapest possible way to honour this.
- **Independent expenditures are never contributions.** v1 ships no IE figures; nothing may imply PAC contributions include them.
- **All IDs, ZIPs and FIPS are VARCHAR.** Leading zeros matter.
- **Every published figure names the filing period it covers.**
- **Every district renders its map vintage.** 35.42% of 2024 district dollars sit on a map that is no longer the law; a superseded district that renders like a current one is a false statement.
- **An exact ZIP answer and a prefix answer are never equated.** `resolution` is carried and rendered.
- **$0 infrastructure.** No cloud write — no bucket, no upload, no deploy — without asking the user. This plan performs none; upload is a separate, approved step.
- **Nothing competes with tile fetches on cellular.** No render-blocking asset, no per-frame filter, no ad script before map idle.
- Thresholds are ratcheted to the achieved value and every gate is verified failable.

## What was cut from v1, and why

Recorded so nobody re-adds it by accident.

| cut | reason |
|---|---|
| **Individual aggregates** (`itcont.txt`, 10.28 GB) | The site is PAC-centric *by design* — that is the legal foundation, not a shortfall. Cutting it removes the largest download, the k≥5 suppression machinery, and the only task whose mistake is a release blocker. |
| **Independent expenditures** | The bulk CSV sums to $15.8bn from registered spenders against pas2's authoritative **$4,497,565,949**. Nine rows from unregistered filers alone total $33.9bn, and single $9.9bn filings appear from committees named "THE COURT OF DIVINE JUSTICE". Shipping a number we cannot reconcile would break the project's entire ethic. Deferred until the hygiene rule that closes the residual is measured — not papered over with a threshold chosen to make it look right. |
| **Candidate profile pages** (`08_profiles.py`) | The district page carries the top PACs inline. A page per candidate is v1.1. |
| **`11_upload_r2.py`** | Phase 7. First cloud write in the project; needs explicit approval. |

The OpenFEC sweep (`01b_totals.py`) is **optional for v1**: the itemized/unitemized band exists for *individual* money, which v1 does not show. The key is registered and the sweep is ~54 requests, so run it if convenient, but it blocks nothing.

```python
"""What goes into a tile, and in what units."""

from decimal import Decimal

#: Tiles carry ONLY what the choropleth paints. Everything else is a
#: sidecar, so a new statistic never costs a tile rebuild and a new
#: immutable filename.
TILE_PROPERTIES = ("district_geoid", "pac_cents", "map_status")


def to_cents(amount):
    """Dollars -> integer cents. Never float: tile encoders round
    differently and a cent that moves between rebuilds changes a hash."""
    return int((Decimal(str(amount)) * 100).to_integral_value())
```

### Task 4: The riso design system

The visual thesis: **registration quality encodes certainty.** This project's hardest honesty problem is that precision varies — superseded maps, prefix-resolved ZIPs, an area-weighted crosswalk. Risograph's native language is imprecision made visible, so crisp registration means exact and an offset plate with open halftone means approximate. It is the structural heir to follow-the-ppp's `geo_precision`, in ink.

**Palettes are validated, not chosen.** Classic riso inks FAIL the checks: Federal Blue reads gray (chroma 0.089), orange↔green is ΔE 7.3 under protanopia, and two inks fall below 3:1 against the paper. The values below are the snapped, passing set — do not substitute swatches off a riso ink chart without re-running the validator.

**Files:** Create `web/src/styles/riso.css`, `web/src/lib/riso.ts`, `web/src/lib/riso.test.ts`

```ts
/**
 * The riso ink system.
 *
 * Registration quality encodes certainty: a crisply registered fill is an
 * exact answer, an off-register fill with open halftone is an
 * approximation. Same grammar for both kinds of approximation this data
 * has — a ZIP resolved by prefix, and a district drawn from a map that is
 * no longer the law.
 *
 * These hexes are VALIDATED, not picked. Raw riso inks fail: Federal Blue
 * reads gray at chroma 0.089 and orange/green collide at ΔE 7.3 under
 * protanopia. Re-run the dataviz validator before changing any of them.
 */

/** Categorical ink order. Fixed — a 6th sector folds into "Other". */
export const INKS = [
  "#2F4B9B", // federal blue
  "#FF48B0", // fluorescent pink
  "#1F7A4D", // green
  "#C2410C", // orange
  "#7E5BB0", // purple
] as const;

/** Single-ink tone, light -> dark. Monotonic in OKLab L. */
export const DENSITY_RAMP = [
  "#E8EDF7", "#C3CFE8", "#8FA3D1", "#5C76B8", "#2F4B9B", "#1B2F6B",
] as const;

const APPROXIMATE = new Set(["zip3_prefix", "cd119_superseded"]);

export function certaintyClass(marker: string): string {
  return APPROXIMATE.has(marker) ? "riso-offregister" : "riso-registered";
}

/**
 * The ink for a sector, keyed to a stable global order rather than to
 * whatever happens to be on screen. SECTOR_ORDER comes from stage 04's
 * sector table; anything past the fifth slot folds into "Other", because
 * a 9th series is never a generated hue.
 */
export const SECTOR_ORDER = [
  "Corporate", "Labor", "Trade Association", "Membership", "Party",
] as const;
export const OTHER_INK = "#6B6B66";

export function inkForSector(sector: string, _visible?: string[]): string {
  const i = SECTOR_ORDER.indexOf(sector as typeof SECTOR_ORDER[number]);
  return i === -1 ? OTHER_INK : INKS[i];
}

export function densityStep(value: number, breaks: number[]): string {
  let i = 0;
  while (i < breaks.length && value > breaks[i]) i++;
  return DENSITY_RAMP[Math.min(i, DENSITY_RAMP.length - 1)];
}
```
