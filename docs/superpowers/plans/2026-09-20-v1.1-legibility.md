# v1.1 — legibility: motion, party, and a way in

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:subagent-driven-development` (recommended) or
> `superpowers:executing-plans` to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** make the map readable — each district's screen moves on its own
phase at a finer grain, an incumbent-party layer in red and blue, state
borders you can find before you find 436 districts, and a way into a state and
a district by double-clicking.

**Architecture:** no new dependencies and no new renderer. Every change is
either a column added in stage 07, a constant or uniform in the existing
WebGL2 press, or DOM the app already owns. The party layer is a *layer*, like
the Senate layer — a toggle, never a merge into the money encoding.

**Tech Stack:** DuckDB + Python for artifacts; Vite + React + TypeScript;
WebGL2 fragment-shader halftone (`web/src/lib/plate.ts`); Playwright harness
(`web/check.mjs`).

**Spec:** `ROADMAP.md` §"v1.1 — the direction from 2026-09-20", plus the two
decisions taken 2026-09-20 and recorded here:

1. **Party is a red/blue fill with fewer money steps** — not a keyline, not
   six steps. Measured below.
2. **Three zoom tiers** — nation → state → district.

**Read `CLAUDE.md` first. Its invariants are binding and this plan does not
restate them all.**

## Global Constraints

- **No individual is ever named.** Not in a UI, an artifact, a tile or a
  download. Nothing in this plan touches `itcont.txt`; keep it that way.
- **Independent expenditures are never contributions.** Nothing here changes
  what is summed; if you find yourself writing a new money query, it is 24K
  and 24Z only.
- **All IDs and ZIPs are VARCHAR.** `CAND_ID`, `district_geoid`, FIPS,
  district numbers. `cd` is a two-character string and `'00'` is a real
  at-large value — never int.
- **`CELL`'s *ratio* is the certainty encoding**, not its absolute size.
  3.6 / 5.6 / 8.4 px is current / contested / superseded, a 2.33× spread that
  says "173 of 441 districts sit on a map that is no longer the law". Scale
  the whole table together or the map starts claiming something else.
- **Reduced motion must move nothing**, and that is asserted on the GL calls,
  not on pixels. Task 3 changes how motion is produced, so it changes what
  that assertion has to watch. Do not let it degrade into a check that passes
  while testing nothing — this repo has shipped that twice
  (`web/prototypes/COMPARISON.md` §14, and the v1 tooltip check).
- **Every acceptance check must be verified failable.** Run it against the
  code before the fix and watch it fail. A check nobody has seen fail is a
  check nobody should trust.
- **Build before you verify.** `node web/check.mjs` runs against

## The measurement this plan rests on

The user asked for a red/blue party scale where darker means more money. That
is prototype E, and round 2 measured E failing: REP↔DEM separate by ΔE 6.5 at
the lowest money step against a hard floor of 15, clearing it only on the top
two steps — 147 of 441 districts. `COMPARISON.md` §12 gives the cause, and it
is structural: *lightness encodes money by putting less ink down, and less ink
is less hue.*

**Measured again on 2026-09-20, and E's numbers reproduce exactly** (6 steps,
floor 0.34 → worst normal ΔE 6.5, worst CVD 5.4). Raising the coverage floor
buys party separation and spends the money axis, and with E's inks nothing
clears both gates:

| steps | floor | worst normal ΔE (≥15) | worst CVD ΔE (≥8) | min ΔL (≥0.06) |
|---|---|---|---|---|
| 6 | 0.34 | 6.5 | 5.4 | 0.071 |
| 6 | 0.68 | 14.9 | 12.1 | **0.025** |
| 4 | 0.60 | 12.7 | 10.3 | 0.062 |
| 3 | 0.68 | **14.9** | 12.1 | 0.065 |

**But E's inks carried a constraint this layer does not.** E mixed REP,
neutral and DEM continuously, so its inks had to be iso-lightness *and* its
chroma was capped at "the highest that still passes the money axis". An
incumbent party is **categorical** — a district is pure REP or pure DEM, and
never a mixture. The only constraint that survives is that the two ramps print
at equal lightness, so a red step 2 and a blue step 2 read as the same money.
Chroma is free.

Searching two inks under that weaker constraint, **four money steps clear both
gates in both stocks** — 152 passing pairs in light, 76 in dark, and none at
five or six steps. The pair adopted below is not the highest-scoring one; it
is the highest-scoring pair that still reads as *red and blue* rather than
brick and violet, on the same principle that kept F's semantic hues.

**Adopted, measured on the shipped ink model:**

| | light | dark |
|---|---|---|
| paper | `#F5F3EE` | `#17171A` |
| REP ink | `#a80009` | `#d1000e` |
| DEM ink | `#0045c7` | `#0156ef` |
| floor | 0.50 | 0.34 |
| REP coverages | `[0.50, 0.6089, 0.7327, 0.88]` | `[0.34, 0.5213, 0.6976, 0.88]` |
| DEM coverages | `[0.50, 0.6228, 0.7468, 0.88]` | `[0.34, 0.5202, 0.6937, 0.88]` |
| REP printed ramp | `#c97a7a #bf5f61 #b44245 #a81e23` | `#5b171f #7f1721 #a21723 #c61726` |
| DEM printed ramp | `#7b96d6 #5d80d0 #3f69ca #1e50c3` | `#173367 #174290 #1850b8 #185fe2` |
| worst normal ΔE | **16.7** (≥15) | **16.7** (≥15) |
| worst CVD ΔE | **13.6** (≥8) | **13.1** (≥8) |
| cross-step ΔE (red *i* vs blue *i+1*) | 20.0 | 21.7 |
| min adjacent ΔL | 0.062 (≥0.06) | 0.068 (≥0.06) |
| money axis | all ordinal checks pass | light-end contrast 1.35:1 — see below |

**Two departures, both on the record:**

- The two parties have **their own coverage tables**. They differ slightly
  (`0.6089` vs `0.6228`) precisely so the printed lightness matches; that is
  what makes the money comparable across parties. Do not "tidy" them into one.
- **Dark stock fails the 2:1 light-end contrast gate at 1.35:1**, the same
  departure `inks.ts` already records for D's money ramp and for the same
  reason: a district carries a keyline, so the fill only has to carry order.
  Record it in the header the way D's is recorded. Do not silently fix it by
  raising the floor — that costs the ΔL gate, which is the one that matters.

```python
def incumbent_party(rows):
    """Which party holds this seat, from FEC's own CAND_ICI.

    `rows` is the filed incumbents for one district as (party,) tuples.

    Four cases, and the last two are NOT a default to one party. Measured
    2026-09-20: 414 of 441 districts have exactly one filed incumbent for
    2026 (416 for 2024); 7 have several, because redistricting puts sitting
    members in new seats, and 20 have none. Painting those 27 red or blue
    would state something false about 6% of the map, so they get their own
    values and the UI renders them as their own case.
    """
    parties = [r[0] for r in rows]
    if not parties:
        return "none"
    if len(parties) > 1:
        return "several"
    party = parties[0]
    return ("REP" if party in REP_CODES
            else "DEM" if party in DEM_CODES else "OTH")
```

```ts
 * THE PARTY LAYER — which party holds the seat, and how much PAC money it
 * took. A LAYER, never merged into the money map.
 *
 * Four money steps, not six, and that is the whole finding. Round 2's E put
 * party in the hue and money in the lightness and measured it failing:
 * REP↔DEM separate by ΔE 6.5 at the bottom step against a hard floor of 15,

 * structural — lightness encodes money by putting LESS INK down, and less

 *

 * and DEM continuously, so its inks had to be iso-lightness AND its chroma
 * was capped at the most the money axis would take. An incumbent party is
 * CATEGORICAL: a district is pure red or pure blue and never a mixture. The
 * only constraint that survives is that the two ramps print at equal
 * lightness, so a red step 2 and a blue step 2 read as the same money.
 * Chroma is then free, and at four steps both gates clear:
 *
 *              worst normal ΔE   worst CVD ΔE   cross-step   min ΔL
 *     light         16.7             13.6          20.0       0.062
 *     dark          16.7             13.1          21.7       0.068
 *     gate          15               8             15         0.06
 *
 * Measured over 152 passing light pairs and 76 dark; NONE passed at five or
 * six steps. The pair below is not the top scorer — it is the top scorer
 * that still reads as red and blue rather than brick and violet, the same
 * call F made when it kept its semantic hues over marginally better ones.
 *
 * TWO TABLES ON PURPOSE. tableRep and tableDem differ (0.6089 vs 0.6228)
 * because that is what makes the printed lightness match. Collapsing them
 * into one puts party back into the money axis.
 *
 * DARK STOCK FAILS THE 2:1 LIGHT-END CONTRAST GATE at 1.35:1. Deliberate,
 * and the same departure this file already records for D: a district fill
 * carries a keyline, which is the heaviest mark on the plate, so the fill
 * only has to carry ORDER among four classes. Raising the floor to fix it
 * spends the ΔL gate, which is the one that carries the money.
 */
export const PARTY = {
  inkRep: "#a80009", inkDem: "#0045c7",
  inkRepDark: "#d1000e", inkDemDark: "#0156ef",
  tableRep: [0.50, 0.6089, 0.7327, 0.88],
  tableDem: [0.50, 0.6228, 0.7468, 0.88],
  tableRepDark: [0.34, 0.5213, 0.6976, 0.88],
  tableDemDark: [0.34, 0.5202, 0.6937, 0.88],
  STEPS: 4,
} as const

/** The four printed tones for one party. Derived from the ink and the table
 *  the way D's ramp is derived — never typed, so the legend cannot drift
 *  away from the plate. */
export function partyRamp(party: "REP" | "DEM", dark: boolean): string[] {
  const ink = dark
    ? (party === "REP" ? PARTY.inkRepDark : PARTY.inkDemDark)
    : (party === "REP" ? PARTY.inkRep : PARTY.inkDem)
  const table = dark
    ? (party === "REP" ? PARTY.tableRepDark : PARTY.tableDemDark)
    : (party === "REP" ? PARTY.tableRep : PARTY.tableDem)
  const paper = dark ? D.paperDark : D.paper
  return table.map((c) => plateTone(paper, [ink], splitInk(c, [1]), dark))
}
```

- Produces: `press.setPhaseAmp(v: number)`; `STRIDE_FLOATS` becomes 8.

**What is there now.** `uDrift` is a `vec2[3]` uniform — one drift per plate
for the whole sheet — and the entire map is a single `drawArrays`. That is why
it slides as one sheet. The vertex layout is 7 floats
(`aPos` 2, `aCov` 4, `aCell` 1) at offsets 0, 8, 24 (`plate.ts:47`, `:347-352`).

**The approach:** give each district a phase in `[0,1)` as a vertex attribute
and rotate its drift by that phase in the shader. Still one draw call, still
one global angle per plate — one angle per plate for the whole sheet is what
makes it a press rather than 436 presses, and that does not change.
